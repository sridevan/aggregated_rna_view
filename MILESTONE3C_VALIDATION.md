# Milestone 3C validation: Family Overview reorganisation and ProtVista-style Annotations

Date: 2026-10-16. Frontend only; backend, Rfam mappings, family aggregation files and the clustering worktree (`../aggregated_rna_clustering`) untouched.

## What changed
- **Family Overview** now holds the three interconnected structural views: the sequence/structural-coverage/alignment-confidence tracks with the selected-instance state track (moved unchanged from the old Annotations tab), the PDBe RNA 2D viewer and the PDBe Mol* 3D viewer, inside the "Molecular view" card (`frontend/src/components/StructureExplorer.tsx`, formerly `AnnotationsTab.tsx`, rendered by `FamilyOverview.tsx`). Layout order: About → stat cards → Molecular view (selector, tracks, legend, selection summary, 2D | 3D) → representative/methods | species → consensus model.
- **One shared instance selector** (`instance-select`) defaults to the display representative 4FE5 chain B (rule unchanged) and lists every Rfam-mapped chain instance (84; chains of one entry stay separate, e.g. 3RKF A/B/C/D, 5E54 A/B). Changing it updates Mol*, the 2D viewer (or its explicit "no 2D topology" state), the instance track and the translation of the consensus selection; `SelectionContext` keeps consensus positions across instances and never fabricates residues (deleted / uncovered / no-coordinate positions are listed, not highlighted).
- **Selection synchronisation** is unchanged in mechanism (Rfam consensus positions as the shared coordinate; clicks in the tracks, 2D and 3D viewers all go through `SelectionContext`).
- **Annotations tab** (`AnnotationsTab.tsx`, new) shows only ProtVista-style aggregated tracks on the same consensus axis (same cell geometry as the coverage tracks): two collapsible categories, *RNA 2D structure* (HL, IL, JL = J3 ∪ J4) from `tracks.json` and *Ligand binding sites* (one track per CCD id in the default track, 29 for RF00167) from `tracks.json` + `ligands.json`, loaded lazily on first visit. Tooltips give loop observations / instances / entries / denominators / motif groups, or ligand identity, consensus position, supporting PDB entries (counted per entry, not per chain) and conservation (sequence coverage, structural coverage, mean PP). Clicking a bar toggles the shared consensus selection, so Family Overview highlights follow. No instance selector or viewers in this tab.
- Types/loaders: `types/backend.ts` (TracksDataset, LigandsDataset), `api/data.ts` (`loadTracks`, `loadLigands`), `state/useAnnotations.ts`.

## Limitations
1. **RNA 2D representation is per-instance from PDBe (topology + FR3D), not reference-derived**, so it is genuinely instance-specific where PDBe provides it; 24 of 84 instances (e.g. 9NBC/9NBH/9NDD) have no PDBe 2D topology and show an explicit unavailable panel. There is no family-level (consensus) 2D diagram yet.
2. The "RNA 2D structure" annotation category uses the Motif Atlas FR3D loop tracks (observed loops, HL/IL/JL as requested); the BGSU reference-element track (P1–P3, L2, L3, J1/2…) exists in `reference_structural_elements.json` but is not displayed. Say the word and it becomes a fourth, clearly labelled "reference-transferred" row.
3. Junction loops are the union of J3 and J4; the tooltip shows the J3/J4 breakdown, and the FR3D hairpin on the J2/3 strand (HL_56046.1) stays in the HL track.
4. Ligand tracks are entity-level (chain attribution unresolved for 12 multi-copy entities) and default-class only: metals, additives and flagged terminal GTP are excluded from the default tracks but retained in the data (8 CCD ids); bar height = fraction of that ligand's entries that contact the position.
5. Scaffold-only positions (consensus 1–18, 88–102) show loop bars from the 8 scaffold chains of 9NBH/9NDD; the tooltip's denominators make the small base explicit.
6. 2D-viewer clicks report label_seq_id for the author chain; the viewer cannot show residues without coordinates.

## Single-nucleotide selection and viewer focus (2026-10-16)
- `state/selection.tsx`: one active selection or none. Kinds: `position` (one Rfam consensus position; preserved across instance changes and re-resolved through the new instance's mapping), `residue` (one instance-bound nucleotide without a consensus coordinate; cleared on instance change) and `group` (an annotation group with exact, possibly discontinuous membership: id, label, type HL/IL/J3/J4, source entry/instance, members with unit id, consensus position or null, seq_name and label_seq_id, and segment boundaries). The selected instance is held separately and never alters the selection. `toggle(pos)` selects or, when already selected, clears; there is no range or multi-select API. Nothing creates groups yet; the derived `positions` / `instanceResidues` sets already handle them, so future BGSU loop tracks only need to call `selectGroup`.
- `ConsensusTracks.tsx`: click selects one column (shaded); shift has no effect. Toolbar: "Select" input follows the same rules; `selection-status` states concisely what the selection resolves to in the current instance ("Consensus 39 is deleted in 9NBH A: nothing highlighted", "…no experimental coordinates…", "…not covered by the alignment…", or the highlighted residue).
- `PdbeMolstarViewer.tsx`: new `focusOnSelection` prop (used by the Family Overview). After the selection is coloured, the camera is centred on the residue(s) with `camera.focusLoci(extraRadius 8 Å, minRadius 14 Å)`, keeping the view direction so neighbouring nucleotides stay in view; no structure reload; replacing the selection re-centres; clearing removes the colour and leaves the camera untouched; after an instance switch the new structure is loaded, oriented, fitted and then the preserved position is highlighted and focused. "Reset orientation / Fit" restores the family view; "Focus selection" re-centres.
- 2D viewer: unchanged mechanism (clear + select by label_seq_id); it restores unselected nucleotides to its default text colour.
- Annotations tab is independent: a click pins a local details panel (`annotation-inspect`) and shades the column locally; it never touches the shared selection, the selected instance, Mol* or the active tab. Hover tooltips unchanged.
- Tests: `single-selection.spec.ts` (replace / clear / no shift range / Mol* highlight + camera target within 1.5 Å of the residue centre / 2D mirror; instance switching 1Y26 X, 5E54 A, 5E54 B with re-focus; 6P2H uncovered and 9NBH deleted / no-coordinate positions reported and not highlighted), `annotation-tracks.spec.ts` (independence), updated `annotations.spec.ts`, `overview-layout.spec.ts` (selection centres the camera, direction kept), `refinements.spec.ts`. Suite: 12 vitest + 26 Playwright (all passing).
- Fixed two races exposed by switching the instance while the first structure is still loading (the cause of the "selection does not reliably highlight or centre" report): (1) `PdbeMolstarViewer` kept the previous structure's region-component reference, so the new structure's region was never built while all default components were hidden, leaving an empty scene in which Mol* silently drops camera resets and focus; the region reference is now reset inside the load queue, verified against the state tree, built after the structure data resolves, and an empty scene is never produced. (2) `PdbRnaViewer2D` rendered into a shared container, so a late render could overwrite the current topology; each render now uses its own child container.
- 2D viewer: after applying a selection the drawing is re-fitted (the PDBe RNA Viewer pans to a selected residue), so the whole topology stays visible.

## Annotation track refinement (2026-10-16, PDBe-KB style)
- `AnnotationsTab.tsx`: fixed-size marks (16 px high, one cell wide; rows 30 px) in a shared coordinate system: each row is an HTML label column (176 px, label + sub-label + ⓘ info popover) plus an SVG whose viewBox spans exactly CLEN cells, stretched to the row width, so every mark has identical dimensions and all rows and the HTML axis align. Value is encoded by colour through a per-track `ScaleDef` (kind, label, light/dark palette, bins); today two frequency scales (teal for Motif Atlas loops, blue for ligand contacts, 5 bins) with a generated legend; a quantitative scale (e.g. median RSA) only needs another `ScaleDef`, so single-track categories for predicted pockets and solvent accessibility slot in without a layout change. Grey marks = no evaluable structure at the position (denominator 0); empty = evaluated, not annotated. Frequencies and denominators are unchanged from Milestone 3B.
- Categories: header outside a body that scrolls vertically beyond 220 px (natural height below); no horizontal scrolling; tooltips and popovers are fixed-positioned and never clipped.
- Tooltips: loops "Rfam residue N / Type: Hairpin loop (HL) / Observed in k RNA instances" (k = distinct chain instances from `tracks.json`; JL = union of J3 and J4, never summed); ligands "Rfam residue N / Ligand: CCD — Name / Observed in k PDB entries" (distinct entries). Motif-group ids, loop ids, J3/J4 split, denominators and PP confidence stay out of tooltips; the click-to-pin panel keeps them under "Evidence details".
- ⓘ popovers: loop tracks explain HL/IL/JL segment architecture, the Motif Atlas source, one observation per loop, and that loop architectures differ between instances (not a shared secondary-structure assignment); ligand tracks explain PDBe entity-level data, consensus mapping, per-entry aggregation, non-independent chains and the lack of chain-specific proof.
- Download annotations (JSON): links to the existing Milestone 3B files `tracks.json`, `loops.json`, `ligands.json`, `reference_structural_elements.json` (loop ids, HL/IL/J3/J4 classes, motif groups, exact nucleotide and segment membership, entries/instances, consensus mappings, CCD ids and names, numerators/denominators, coverage, availability, provenance, PP confidence). No new files generated.
- Independence from Family Overview unchanged. Tests: `annotation-tracks.spec.ts` rewritten (mark geometry and colour vs `tracks.json` frequency, axis alignment, concise tooltip texts and counts, popovers, scrolling with fixed header, collapse, download hrefs and JSON content, 390 px layout, independence). Screenshot `docs/screenshots/m3c_annotations.png`.
- Limitation: RF00167 has no position with a zero denominator, so the grey "no evaluable structure" state is not visible in the demo family; ligand tracks remain entity-level (see 3B).
