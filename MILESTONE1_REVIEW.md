Contract notes for the frontend:
- `alignment_state` is one of `match`, `insert`, `local_end`, `not_submitted_flank`; only `match` has `rfam_consensus_pos`; `insert` and `local_end` carry `insertion_anchor` (0..CLEN) and `insertion_offset` (>= 1); the schema enforces this.
- `consensus_columns` has exactly CLEN entries per chain with state `match`, `deletion` (inside the aligned model span) or `uncovered` (outside it).
- `has_coordinates` comes from `atom_site`; a `match` residue with `has_coordinates: false` is a sequence-level observation only.
- `posterior_prob` is the Infernal bin midpoint (`pp_bins`), `posterior_prob_char` the raw annotation; display bands high >= 0.95, medium >= 0.80 are provisional.
- Mol* selection: use `label_asym_id` + `polymer_seq_position` (label_seq_id) or `auth_asym_id` + `author_residue_number` + `author_insertion_code`; both are present per residue.

## Representative-selection rationale

Rule (documented in `rna_explorer/instances.py`): among clan-best instances take the one with the most consensus-matched residues that have coordinates; ties broken by lowest resolution, then lowest PDB id.

Ranking for RF00167: 9ndd chains A-D (98 matched residues, all with coordinates, 2.67 A cryo-EM) precede 4tzx/X (69 residues, 2.01 A X-ray, Vibrio vulnificus adenine riboswitch). 9ndd/A wins on the first criterion because its construct spans the whole model (consensus 1-102, 96 % of CLEN) whereas natural aptamer-domain crystals cover consensus 19-87 (67-69 residues). The tie among the four 9ndd chains resolves to chain A by pdb_id and then by instance order (chains of one entity are identical).

Caveat: 9ndd is a synthetic scaffold-embedded 8-oxoguanine riboswitch variant. The rule optimises model coverage and coordinate completeness, which is what the overview needs for a full-length consensus display, but a user may expect a natural, ligand-bound, high-resolution X-ray structure such as 4tzx. The data to support an alternative rule (organism, method, resolution, ligand presence after Milestone 3) are already in `instances.json`; no backend change is made now.

## Known limitations

1. Organism is taken from the PDBe search API with mmCIF fallback; synthetic constructs derived from natural sequences are labelled "synthetic construct" (41 API/mmCIF disagreements). Natural origin is not inferred.
2. PP display bands use bin midpoints, so Infernal's '8' bin (0.75-0.85) is "medium".
3. Clan competition relies on the `clan` field of the Rfam family JSON; families without a clan skip it (correct) but a missing field would silently skip too.
4. RF00177 is covered only by offline regression tests on the POC alignment; the full RF00177 build (1473 ribosome entries) has not been run through the package.
5. The per-chain mapping file includes all residues of the chain (flanks included) and the consensus-column table; files are 36-73 kB for RF00167 and will be ~0.5 MB for 16S chains.
6. No automated check that the Rfam release used for the CM matches the release behind the PDBe mapping; agreement of model and region spans (84/84) is the only evidence.
7. `experimental_method` and `resolution` come from the PDBe search API per entity; for multi-method entries only the first value is kept.

## Recommendations for Milestone 2

1. Load `family.json`, `instances.json`, `consensus_stats.json` at start; fetch `mappings/<seq_name>.json` lazily when a structure is selected.
2. Keep the selection state in consensus coordinates (set of consensus positions plus optional anchor/offset for insert residues) and translate to PDB residues through the selected chain's `consensus_columns`; this is what lets the user switch structures while keeping the selection, and it is the hook for a later 2D viewer.
3. Render deletion and uncovered positions differently (gap vs out-of-range) and grey out `match` residues without coordinates in 3D-linked views.
4. Treat `is_clan_best == false` instances (none in RF00167, four in RF00177) as hidden by default.
5. Structural similarity and clustering data do not exist yet; the Structures tab must show an explicit "pending" state for those panels.
6. Consider exposing `pp_display_thresholds` and the representative rule in the UI as provenance text, since both are provisional.
